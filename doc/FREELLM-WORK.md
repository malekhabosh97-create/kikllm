# تشغيل FreeLLM Work

تخصيص لبيبركليب يحتفظ بالشركات والهيكل التنظيمي والمهام والمشاريع والمهارات والمراجعات، ويضيف تنفيذ العمل عبر حسابات مواقع المحادثة. لا يتطلب مفتاح خدمة مدفوعة للنماذج.

## الاستخدام

1. شغّل التطبيق وافتح **المتصفح**. افتح المنصة وسجّل دخولك يدويًا.
2. اختر الشركة ثم **مساحة الفريق**. اربط مجلد المشروع.
3. اختر المدير ومنصة حسابه، ثم اشرح المطلوب. وضع **تنفيذ مشروع** يفرض العمل والتحقق؛ وضع **نقاش** يسمح بإجابة فقط.
4. تابع الملفات والمهام والفريق والمعاينة في الشاشة نفسها. يمكن إيقاف التشغيل صراحة؛ مغادرة الصفحة لا تلغيه.

إغلاق نافذة البرنامج يخفيه في شريط النظام. خيار **إنهاء البرنامج والخدمات** ينهي الخدمات التابعة له. إغلاق تبويب منصة ينهي ذلك التبويب فقط؛ لا تستخدمه لإخفاء العرض.

## ما يعمل

- متصفح مدمج مع جلسة حساب دائمة لكل منصة. الحسابات لا تُخزن في إعدادات الوكلاء.
- محادثة مستقلة لكل شركة ووكيل ومشروع ومهمة ونمط نموذج. تعريف الدور مرة عند بدء المحادثة؛ تحديث سياق المشروع يرسل منفصلًا.
- انتظار تسجيل الدخول والتحقق البشري مع إمكانية إيقاف التشغيل.
- طابور لكل حساب لمنع تداخل الطلبات. تُفتح محادثات الوكلاء عند الحاجة، مع الاحتفاظ بروابط المحادثات لاستعادتها.
- محرك تنفيذ موحد للدردشة وتشغيل المهام عبر المجدول، مبني على LangGraph وحفظ نقاط التنفيذ في قاعدة البيانات.
- إنشاء المختصين، مهام أصلية وأبناء، تفويض مع طلب تشغيل حقيقي، وإعادة تنبيه المدير بعد اكتمال الأبناء.
- قراءة وبحث وتعديل الملفات، فروق فعلية، بصمات تمنع الكتابة فوق نسخة تغيرت، ونسخ سابقة محلية.
- تشغيل أوامر واختبارات، والتحقق من الملفات والتسليم. الفحص الفارغ لا ينجح.
- تشغيل المعاينة عبر خدمات مساحة العمل الأصلية وفحص استجابة صفحتها.
- البحث العام، وقراءة المصادر، والبحث في مستودعات البرمجة وكتالوج النماذج والبيانات، مع ملاحظات للمشروع.

## بروتوكول الرد والتسليمات

- كل رد من الموديل يُصنّف في `protocol.ts`: استدعاء أداة، أو استدعاء غير صالح، أو سؤال، أو عائق، أو تسليم، أو إجابة.
- استدعاء واحد فقط يُنفّذ في كل رد؛ أي استدعاءات إضافية تُبلّغ للموديل بأنها `NOT_EXECUTED`. الكتلة المسبوقة مباشرة بعبارة مثال تُعامل كتوضيح، دون فحص الرد كله.
- الاستدعاء غير المطابق للمخطط لا يُنفّذ، ويُرسل للموديل سبب محدد مع محاولتي تصحيح كحد أقصى، ثم يتوقف التشغيل بعائق واضح.
- ينهي الموديل الرد غير الأداتي بسطر حالة: `[[STATUS: delivered]]` أو `[[STATUS: question: ...]]` (حالة `waiting_input`) أو `[[STATUS: blocked: ...]]`.
- `work-kind.ts` يحدد نوع العمل (برمجة، صورة، فيديو، بحث، مستند). عندما تكون الصورة أو الفيديو هي المنتج، لا يكتمل التشغيل إلا بوجود ملف حقيقي مُتحقق منه؛ الوصف أو السيناريو لا يُعتمد.
- `deliverables.ts` يفحص بايتات الملف (PNG/JPEG/GIF/WEBP/SVG، ومدة MP4/MOV، وترويسة WEBM)، ويحفظ سجلًا بإصدارات في `.freellm/deliverables.json`. يسقط الدليل تلقائيًا إذا تغيّر الملف. المراجعة البصرية أو السمعية غير مُدّعاة (`humanOrVisualReview: "not_performed"`).
- أدوات جديدة: `register_deliverable` و`save_media_from_url` و`list_deliverables`. فشل تنزيل صورة محمية بجلسة الموقع يُسجّل كعائق بدل تجاهله.

## الحدود التي يجب فهمها

- كثرة تعريفات الوكلاء لا تعني أن الحساب المجاني يتحمل طلبات كثيرة في اللحظة نفسها. حدود الموقع والذاكرة تبقى نافذة.
- أُثبت الاتصال والتنفيذ الفعلي عبر جيمناي في حساب المستخدم. ديب سيك وبقية المحولات تحتاج تسجيل الدخول ومعايرة حية قبل اعتمادها.
- اختيار الوضع الحالي لا يثبت اسم إصدار معين. لا يوجد انتقال صامت إلى نموذج آخر إذا تعذر الاختيار المطلوب.
- أداة الطرفية تعمل بصلاحيات حساب النظام؛ اختيار مجلد المشروع ليس عزلًا على مستوى نظام التشغيل. تعطيل الأوامر يمنع الاختبارات التي تحتاج طرفية أيضًا.
- ظهور حالة غير محسومة يمنع إعادة إرسال الطلب تلقائيًا. افحص التبويب، ثم استخدم **بدء محادثة جديدة** إذا لزم.
- تشغيل عدد كبير مثل خمسين وكيلًا لم يخضع لاختبار تحميل شامل بعد.
- ترتيب النماذج وفق اختبارات رسمية مهمة بحثية للوكلاء، وليس جدول ترتيب مخترعًا داخل البرنامج.
- إغلاق التطبيق بالكامل يوقف خدماته. الاستمرار على مدار الساعة يحتاج بقاء الجهاز والتطبيق والاتصال متاحة.

## مسارات محلية

- بيانات المتصفح وحفظ المحادثات وسجلات التشغيل: مجلد المستخدم داخل `.paperclip/freellm`.
- سجل فروق الملفات والنسخ السابقة: `.paperclip` داخل المشروع المختار.
- عقد المشروع المشترك الذي يكتبه المدير قبل التفويض: `.freellm/project.md`.
- دليل قبول التنفيذ الحي: `.freellm-runtime/acceptance-result.json` داخل مستودع التطوير، ويظهر أيضًا في محادثة **مطور التحقق**.

## التحقق للمطور

```powershell
node scripts/freellm-desktop-smoke.mjs
node cli/node_modules/tsx/dist/cli.mjs scripts/freellm-session-smoke.ts
cd server
node node_modules/vitest/vitest.mjs run src/__tests__/freellm-browser-execution.test.ts
$env:FREELLM_INTEGRATION = "1"
node node_modules/vitest/vitest.mjs run src/__tests__/freellm-browser-native.integration.test.ts
```

اختبارات قاعدة البيانات تستخدم قاعدة مؤقتة منفصلة. اختبارات المتصفح المعزولة لا تستخدم حسابات المستخدم. تفاصيل الأدلة وحدود الفحوص العامة في خطة التنفيذ المؤرخة.
